## Delivered

US15/17, BR20–27, FIN-03/04/05, AUTH-02, UI-02. Owner `/owner/finance` reads own signed account/period balances, completed-order dish revenue and immutable entries/receipts/reversals. Sole MFA Admin `/admin/settlements` (`/admin/reports` alias) previews/confirms full-month finalization, completed-order corrections, verified manual receipts and full reversal/replacement. Rate-consent routes stay separate. App composes through feature exports; feature API/query/command hooks own requests and account binding.

Reports separate completed_at revenue, booking-month membership and actual receipt/server-reversal activity. Account summary is shown once; signed credit is never clamped or duplicated into another entry. P24 adds actual integer entry_count in report/detail aggregates and OpenAPI so net-zero periods differ from no facts. Open month, missing/late statement and overdue collectible labels derive from dates/amounts; no settlement enum. Current month cannot be finalized in the UI or backend.

Mutation dialogs show concrete target/amount/context before sending. Durable tab intent binds actor/restaurant/path/body/key; storage failure blocks sending, changed cookies fail server account binding, private queries abort and stale replies are dropped. Uncertain settlement creates use original month/complete entry-set reconciliation before retry. An authoritative absent result permits a separately confirmed original retry; reconciliation/cancel never creates a statement. Keyed financial requests recover the original successful fact after commit/response loss/reload.

Approved font/cream-orange identity and distinct owner/Admin shells retained; reference boards10/12 were inspected from the original bundled assets, without modifying HTML. Signed money uses shared exact BigInt formatter. White compact summary cards, a labeled keyboard-focusable local table scroller and native confirmation dialog support360px without page overflow. Vietnamese UI copy includes credit, deadline and reversal meaning.
