## UI and protocol

- `/account` keeps the current personal workspace, semantic tokens and responsive layout. Avatar controls select JPEG/PNG (5MiB maximum), show a pending preview and announce success only after server confirmation. Remove restores initials. Saved avatars also appear in the shared header; unavailable/broken images fall back to initials. Backend decoding strips metadata and center-crops to256×256JPEG using existing media storage.
- The profile initially shows only “Đổi email” beside the current address. Opening the native modal makes no request. Step1 accepts a new address and the current password; step2 accepts the6digit code. Cancel/Escape preserve the current email. Modal restores focus, locks duplicate submissions and retains error/retry context. Passwords/codes never enter browser storage, logs or audits.
- `POST /profile/avatar`: active authenticated account, CSRF/Origin and Idempotency-Key; exact body `{expected_version,image}` where image is null to remove, otherwise `{mime_type,content_base64}`. Response is current self DTO with nullable `avatar_image_reference`. Caller cannot set another account/media ID. Same key/content replays without another asset/version/audit; changed content/key reuse conflicts. Accepted data, request result and audit commit together.
- `GET /account-avatar-media/{id}`: only a current attachment of an active verified account; returns sanitized image/jpeg, nosniff and no-store. Old, missing or claimed attachments are unavailable. This exposes no username, email or account directory. Public image display is the future-review use case; reviews themselves remain separate.
- `POST /profile/email-change`: active authenticated account, CSRF/Origin and Idempotency-Key; `{expected_version,new_email,password}`. Canonical email follows existing registration policy; password is verbatim. Password revalidation and expected-version check precede pending proof. Returns `{challenge_id,expires_in:600,resend_after:60}` only after SMTP succeeds. Current email/session do not change at this step.
- Codes use a separate HMAC domain binding account, challenge and new address, never plaintext storage. Proof is tied to auth_version. Maximum5wrong codes per challenge and10minute expiry; replacing/resending invalidates previous proof. At most5start attempts/account/15minutes, checked before password hashing, and at least60seconds between sends. Start retries preserve their intent key/payload. SMTP is outside transactions; a persisted request may exist after delivery failure. Retry resolves its challenge; deliberate resend uses a fresh key/password and cooldown.
- `POST /profile/email-change/confirm`: same protections; `{challenge_id,code}`. Wrong proofs commit their attempt count without email/audit mutation. Success atomically checks current availability/auth version and email uniqueness, replaces/verifies email, clears pending/registration/recovery proofs, increments profile/auth versions, commits request result and a redacted audit. All previous sessions are revoked. UI explicitly asks the user to log in again with the unchanged username/password. If the success response is lost, login and self DTO resolve the outcome; never auto-submit another change.
- Closed bodies and canonical string IDs remain enforced. Errors:422invalid input/code,403wrong password/current-account mismatch,409stale version/duplicate email/key reuse,429rate limit,503mail/storage unavailable. General profile edits do not reset pending email consent or bypass code verification.

## Storage and migration

Migration `20261027010000_account_profile_identity` is additive. Existing account IDs, credentials, email verification, authority, sessions and historical business rows are preserved. Personal avatar pointer startsNULL; no historical image/email proof is fabricated. Same-account composite FK prevents foreign attachment. Image records retain immutable ownership/object/hash/dimensions; lifecycle markers support replacement cleanup. Account-first locks serialize avatar and email requests; external storage/SMTP remain outside retried transactions. Account pending-email columns are private and excluded from self DTOs.

Superseded media is marked/claimed before byte deletion, with retryable cleanup on later changes. `avatars:cleanup:local` is guarded to disposable local test databases, retries lifecycle cleanup and removes untracked avatars/ objects older than24hours. Production/retained scheduling is a separate operator configuration. No other media prefix is swept. Runtime grants must restrict updates to new account fields and avatar lifecycle columns; identity/object metadata is immutable after INSERT.
