## P34

Product, policy and operations launch review

```text
Execute P34 for V1.0: Product, policy and operations launch review.
Objective: Prepare a concrete commercial release dossier and verify every mandatory gate.
Inputs: Current source/manifests/lockfiles/migrations/tests, versioned contracts, prior acceptance records and approved decision records. Never use fixtures as partner data.
Dependent prompts: Accepted P33 handoff with behavior and verification evidence, not code alone.
Additional prerequisites: P33 acceptance and DEC-12 actual policies/launch criteria; P35 requires explicit approval.
Required reading (repository-relative):
- AGENTS.md
- docs/README.md
- docs/requirements.md
- docs/roadmap.md
- docs/decisions.md
- docs/implementation-status.md
- docs/architecture.md
- docs/development_guide.md
- docs/testing.md
- docs/release-checklist.md
- docs/deployment.md
- docs/account-security.md
- docs/payments-policy.md
- docs/data/migration-plan.md
Inspect git status and preserve unrelated work. Use CodeGraph first when indexed; recheck source because documentation is target design, not implementation evidence.
Change scope: Release checklist, approved Vietnamese notices/agreements, operations/support/partner handoff and release candidate evidence; no deploy action.
Behavior/API/data contract: Validate all versions, decisions and P31–P33 evidence; exact build/migration compatibility, singleton MFA/recovery, verified partners, direct QR/refunds, commission, privacy, backups/alerts/support/rollback.
Acceptance criteria: DEC-12 and every mandatory release gate accepted; named release authority approves a concrete candidate/window. Missing evidence/policies block launch; docs/prompt completion alone never qualifies.
Tests/evidence: Complete release-checklist.md with evidence links/operator/reviewer/date/commit; link/consistency checks and safe preflight.
Verification commands: Inspect current package scripts first. For frontend changes run npm --prefix frontend run lint and npm --prefix frontend run build plus relevant browser tests. For backend changes run npm --prefix backend run lint, npm --prefix backend test, npm --prefix backend run test:e2e and npm --prefix backend run build. For schema/config changes also run npm --prefix backend run prisma:validate and npm --prefix backend run prisma:generate; test reviewed migrations on disposable MySQL 9.2.0. Existing test:integration and frontend test:smoke are limited; add the scoped missing meaningful checks, never claim they cover untested flows. Documentation-only decision work checks links, anchors, examples, paths and Markdown <500 lines; application tests are unnecessary for documentation alone.
Preserve exact string IDs/integer VND/eight-place fraction rates, snapshot immutability, actor-scoped durable keys, current ownership, transaction/audit atomicity and documented account-first lock order. No external calls in retried DB transactions; no process-local mutex as race protection.
Keep ordinary buyer and manager capabilities together, at most one restaurant per account, and exactly one MFA Admin. No role-grant website, driver/custody/splitting, fabricated fee, default commercial rate, AI transcript storage or automatic checkout after login. Preserve approved Be Vietnam Pro/cream-orange identity and Vietnamese product copy.
Resolve necessary TBDs in their owning decision record before dependent implementation; prepare concrete options and obtain the missing decision. Missing answers are not approval. Continue independent authorized preparation, record BLOCKED dependencies and do not mark this prompt accepted while required evidence is absent.
No retained-data reset/destructive push/demo seed or rewriting applied migrations. Operational migrations/account changes require the relevant future task authorization and approved mapping. No production deployment, external messages, real pilot traffic or money movements outside explicit task authorization.
Handoff: Summarize delivered behavior and US/FR/BR/AC/test IDs; list changed files and updated contracts/OpenAPI where enabled; provide exact commands, actual outcomes, environment/versions and sanitized evidence. Separate source inspection, automated results and browser/operational observations. Report NOT CONFIGURED, NOT RUN and BLOCKED with source accurately; state remaining defects/decisions and whether this prompt/version gate was accepted. Keep every Markdown document under 500 lines and update docs/implementation-status.md, BACKLOG.md and affected navigation. A later prompt cannot start dependent work until this acceptance is recorded.
```
