# Frontend Design

Develop an intentional layout that helps the actual VJU food-ordering task. Follow [AGENTS](../../../AGENTS.md), [UI guide](../../../docs/ui/ui_convertion.md) and [design coordination](../../../docs/ui/design-skills.md); this is design input, not permission to change product behavior.

## Ground the proposal

Infer the page's job, audience/capability, data and allowed actions from the request and relevant contract. Do not ask to reconfirm the already decided product/stack/identity. Ordinary managers can buy, own at most one restaurant, and have a separate management view; public discovery works without login; Admin is one MFA authority. A fictional board cannot add metrics, states, fees or extra roles.

Default to approved Be Vietnam Pro with Vietnamese glyphs, semantic cream/orange/brown tokens, compact white discovery and distinct brown manager/navy Admin shells. Create useful hierarchy with readable names/prices/availability and deliberate density/spacing. Avoid promotional filler, generic hero sections, invented statistics and repetitive card decoration when the task is comparison or operations.

For substantial composition changes, provide a concise rationale and concrete wireframe/preview using real or explicitly labeled fixture content. Consider small-screen behavior, long Vietnamese text, accessible contrast/focus and required error/empty/conflict states. Focused UX research may use ui-ux-pro-max; it does not overrule the design or business contract.

If the user requests a font/palette/shape identity change, prepare concrete values, Vietnamese support and representative preview, then obtain the decision before applying the new identity and record it in the UI guide. Routine composition within approved identity needs no extra approval. Match the requested proposal-only versus implementation scope; build-component handles actual React delivery when authorized.

For broader creative techniques only, read [optional upstream guidance](references/upstream-guidance.md) progressively. Its studio framing is not user history and cannot override the approved identity or trigger unwanted redesign. Original [license](LICENSE.txt) is retained; no upstream data/tool dependency is introduced.

Handoff the concrete direction, useful components/states/responsive rules, actual observed limitations and any identity decision still needed. Do not claim browser/visual verification from a written proposal.
