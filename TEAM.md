## Communication

- **Synchronous:** voice/video or live group chat for incidents, urgent blockers, time-sensitive coordination, and discussion needing rapid back-and-forth. Record decisions afterward.
- **Asynchronous:** GitHub Issues for scope, backlog, questions and blockers; Pull Requests for changes, review, checks and acceptance. Use written async discussion for routine status/proposals and keep conversation with the relevant issue/PR.
- **Decision record:** an Issue records problem, options, decision, rationale, owner/date and affected criteria/contracts. A PR links the Issue and records changes, exact checks/results and remaining limits. The assigned A records acceptance. Unresolved policy remains blocked, not guessed. Never put secrets/private data in GitHub.
- **Bad news:** report missed work, failed checks, security/privacy concerns and blockers as soon as known. State what happened, impact, known/unknown facts, containment, help/decision needed and next update time. Mark FAIL/NOT RUN/BLOCKED accurately. For active incidents, alert the security/operations A privately, then create a sanitized Issue.
